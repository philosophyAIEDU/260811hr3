# 그로우패스 — 폴더 구조 · 데이터 구조 · 직무별 요구수준 표 (1단계)

이 문서는 요청서의 "작업 순서 지시 1번" — 폴더 구조, 데이터 구조, 직무별 요구수준 표 — 를
확인받기 위한 문서입니다.

> **[변경 이력]** 원래 요청서는 "로컬 SQLite, 사내망 전용, 클라우드 업로드 금지"를 전제로
> 했지만, 이후 "Netlify에서 배포"로 방향이 바뀌었습니다. 이에 따라:
> - 데이터베이스를 로컬 SQLite 파일 대신 **Netlify DB(Neon Postgres)** 로 변경했습니다.
> - 이 변경은 §7 "개인정보 및 보안 요구사항"의 원래 전제와 다르다는 점을 알려드립니다.
> 아래 표 형식(직원/진단회차/역량점수/추천결과)과 항목 이름은 원 요청서와 동일하게 유지했고,
> SQL 문법만 SQLite → Postgres로 바꿨습니다.
>
> (한때 사이트 전체 접속코드(`/enter`)를 추가했었지만, 사용자 요청으로 제거했습니다.
> 지금은 사번+이름 확인(화면1)과 관리자 코드(/admin)만으로 보호됩니다.)

## 2. 데이터 구조 (Netlify DB / Neon Postgres 테이블 정의)

요청서 "4. 데이터 구조"의 4개 표를 `lib/db/schema.sql`(문서용)과 `lib/db/db.ts`(실제 실행문)에
그대로 옮겼습니다. (테이블/열 이름은 코드에서 다루기 쉽도록 영문으로 만들고, 각 줄에
한국어로 어떤 한글 항목인지 주석을 달았습니다. 원래 SQLite 문법이었으나 Netlify 배포
결정에 따라 Postgres 문법으로 바꿨습니다 — 표 형식과 항목명은 동일합니다.)

| 요청서 표 | 실제 테이블명 | 비고 |
|---|---|---|
| 직원 | `employees` | 사번(`employee_id`)이 기본키. 로그인 없이 사번+이름으로 본인 확인 |
| 진단회차 | `assessments` | 사번당 여러 번 쌓임 → 이력 비교 기능의 기반 |
| 역량점수 | `competency_scores` | 진단 1회당 10행(역량 10개) |
| 추천결과 | `recommendations` | AI가 만든 추천 + 학습 상태(예정/수강중/완료) |
| (추가) 설정 | `app_settings` | 요청서에 없던 표지만, Gemini API 키(공용)를 저장하기 위해 추가했습니다. 키 자체는 git에 올라가지 않고 Netlify DB 안에만 저장됩니다. |

개인이 자기 API 키로 "덮어쓰기"하는 기능은 별도 로그인이 없으므로, **그 직원의 브라우저에만
저장**(로컬 저장소)하고 화면에서 그 값이 있으면 그 값을, 없으면 관리자가 저장한 공용 키를
사용하는 방식으로 만들 계획입니다. (서버 DB에 개인별로 저장하지 않음 — 사번마다 키를 넣게 하면
관리 부담과 유출 위험이 커지므로 브라우저 저장 방식을 제안합니다. 다른 방식을 원하시면 말씀해주세요.)

전체 SQL 정의는 `lib/db/schema.sql` 파일에서 보실 수 있습니다.

## 3. 희망직무별 역량 요구수준 표

`lib/config/jobRequirements.ts`에 정의했습니다. 직무 5개(영업/마케팅/기획/인사/IT) ×

## 4. 그 밖에 이번 단계에서 정한 것

- **Gemini 모델명**: `lib/config/constants.ts`의 `GEMINI_MODEL` 상수 한 곳에서 관리 (`gemini-3.5-flash-lite`)
- **관리자 코드**: `lib/config/constants.ts`의 `ADMIN_CODE` 상수 (기본값 `1234`)
- **역량 갭 기준**: 요구수준 − 현재점수 ≥ 2 이면 "우선 보완"
- **재진단 안내 기준**: 완료 항목 3개 이상 쌓이면 배너 표시
- **휴넷 링크**: 실제 검색 주소 형식을 아직 확인하지 못했으므로, 우선 휴넷 메인 주소로 연결 +
  검색어 클립보드 복사 버튼 방식으로 계획 (요청서 지침대로 주소를 지어내지 않음)

## 5. Netlify 배포로 바뀌면서 새로 정한 것 (사용자 답변 없이 기본값으로 진행)

질문에 답을 받지 못해, 아래 기본값으로 진행했습니다. 언제든 바꿔달라고 하시면 됩니다.

- **DB**: Netlify DB(Neon Postgres) — Netlify 대시보드에서 사이트에 DB를 연결하면
  `NETLIFY_DATABASE_URL`이 자동 주입되고, `lib/db/db.ts`가 이를 사용합니다.
- **사이트 보호**: ~~시작 화면 진입 전 접속코드 입력 화면(`/enter`)을 추가~~ →
  **[업데이트] 사용자 요청으로 이후 제거했습니다.** (아래 12번 항목 참고)
- **관리자 코드**(`/admin`)도 이제 Netlify 환경변수 `ADMIN_CODE`로 바꿀 수 있습니다
  (기본값 `1234`는 그대로 유지).
- **개인 API 키 덮어쓰기**는 원안대로 브라우저 저장 방식으로 진행 예정입니다 (화면7에서 구현).

1. 데이터 구조(4개 표 + 설정 표)가 요청하신 내용과 맞는지
2. 직무별 요구수준 표의 숫자를 이대로 두어도 되는지, 아니면 지금 조정하고 싶은지
3. ~~사이트 접속코드 기본값을 이대로 둘지~~ → 사용자 요청으로 접속코드 자체를 제거함
4. 개인 API 키 "덮어쓰기"를 브라우저 저장 방식으로 진행해도 되는지

  `GAP_ALERT_THRESHOLD`(2) 이상이면 막대가 빨간색으로 바뀌고 "우선 보완" 표시가 붙습니다.

## 10. AI 프롬프트 및 JSON 응답 형식 설계 (+ 화면4 완료)

`npm run build`가 계속 통과하는 상태로 이어가기 위해, 아래 설계를 바로 적용해 화면4까지
함께 만들었습니다. 마음에 안 드는 부분이 있으면 언제든 말씀해 주세요 — 프롬프트는
`lib/gemini/recommendPrompt.ts` 한 파일만 고치면 됩니다.

**개인정보 처리 원칙**: 프롬프트에는 이름·사번을 절대 넣지 않습니다. Gemini에는
"현재직무 / 희망직무 / 커리어목표 / 역량별 현재점수·요구수준"만 전달합니다.

**프롬프트 요지** (`buildRecommendPrompt`):
1. 요구수준−현재점수 격차가 큰 역량을 우선하되 전체 성장도 고려
2. 추천 6~9개를 "사내강의"(플랫폼=휴넷) / "외부주제"(인프런·유데미·코세라 등) / "도서" 3구분에서 섞어서 생성
3. 각 항목에 "3개월"/"6개월"/"12개월" 단계를 배정 (3개월에 최소 1개 이상 포함 → 성장 로드맵)
4. search_keyword는 실제 검색용 키워드만 (URL·ISBN 등 확인 불가한 정보는 지어내지 않도록 명시)
5. reason은 역량 격차·커리어 목표와 연결한 1~2문장
6. JSON 형식 외 다른 문장·마크다운 금지 (+ Gemini generationConfig에 `responseMimeType: "application/json"` 지정)

**응답 JSON 형식**
```json
{
  "recommendations": [
    {
      "category": "사내강의 | 외부주제 | 도서",
      "title": "짧은 제목",
      "search_keyword": "검색용 키워드",
      "platform": "휴넷 | 인프런 | 유데미 | 코세라 | 도서 등",
      "reason": "추천 이유 1~2문장",
      "stage": "3개월 | 6개월 | 12개월"
    }
  ]
}
```
`parseRecommendResponse()`가 이 형식을 검증하고, category/stage 값이 정해진 목록에 없거나
title·reason이 비어 있으면 그 항목만 걸러냅니다. 통과한 항목이 하나도 없으면 오류로 처리해
화면에 "잠시 후 다시 시도해 주세요" 안내가 나갑니다.

**만든 파일**

| 파일 | 역할 |
|---|---|
| `lib/gemini/recommendPrompt.ts` | 프롬프트 생성 + 응답 JSON 검증 |
| `app/api/recommend/route.ts` | GET(기존 추천 조회, AI 재호출 없음) / POST(Gemini 호출 → 검증 → `recommendations` 테이블에 저장, 같은 진단 회차의 기존 추천은 새 결과로 교체) |
| `app/recommend/page.tsx` | 화면4 — 추천이 없으면 "만들기" 버튼, 있으면 3개월/6개월/12개월로 묶어서 표시 + "다시 만들기" + 검색어 복사 버튼 |

- 개인 키가 설정되어 있으면(화면7) 그 키로, 없으면 공용 키로 호출합니다. 둘 다 없으면
  "설정 화면에서 Gemini API 키를 먼저 등록해 주세요" 안내와 함께 설정 화면 링크를 보여줍니다.
- 추천은 진단 회차(assessment_id)당 한 세트로 저장되어, 다시 방문해도 AI를 다시 부르지 않고
  저장된 결과를 그대로 보여줍니다("다시 만들기"를 눌러야 재생성).
- `npm run build` 정상 통과 확인했습니다. (실제 Gemini 호출 결과는 API 키를 등록한 뒤 확인 가능)
