## 1. 폴더 구조 (계획)

승인 후 화면 단계에서 하나씩 만듭니다. 아래는 완성됐을 때의 전체 구조입니다.

│       ├── diagnosis/route.ts        # 진단 제출 · 결과 조회 · 이력 비교
│       ├── recommend/route.ts        # AI 추천 생성 · 저장 · 조회

## 2. 데이터 구조 (SQLite 테이블 정의)

요청서 "4. 데이터 구조"의 4개 표를 `lib/db/schema.sql`에 그대로 옮겼습니다.
(테이블/열 이름은 코드에서 다루기 쉽도록 영문으로 만들고, 각 줄에 한국어로 어떤 한글 항목인지 주석을 달았습니다.)

| 요청서 표 | 실제 테이블명 | 비고 |
|---|---|---|
| 직원 | `employees` | 사번(`employee_id`)이 기본키. 로그인 없이 사번+이름으로 본인 확인 |
| 진단회차 | `assessments` | 사번당 여러 번 쌓임 → 이력 비교 기능의 기반 |
| 역량점수 | `competency_scores` | 진단 1회당 10행(역량 10개) |
| 추천결과 | `recommendations` | AI가 만든 추천 + 학습 상태(예정/수강중/완료) |
| (추가) 설정 | `app_settings` | 요청서에 없던 표지만, Gemini API 키(공용)를 로컬에 저장하기 위해 추가했습니다. 키 자체는 git에 올라가지 않고 `data/growthpath.db` 안에만 저장됩니다. |

개인이 자기 API 키로 "덮어쓰기"하는 기능은 별도 로그인이 없으므로, **그 직원의 브라우저에만
저장**(로컬 저장소)하고 화면에서 그 값이 있으면 그 값을, 없으면 관리자가 저장한 공용 키를
사용하는 방식으로 만들 계획입니다. (서버 DB에 개인별로 저장하지 않음 — 사번마다 키를 넣게 하면
관리 부담과 유출 위험이 커지므로 브라우저 저장 방식을 제안합니다. 다른 방식을 원하시면 말씀해주세요.)

전체 SQL 정의는 `lib/db/schema.sql` 파일에서 보실 수 있습니다.

## 3. 희망직무별 역량 요구수준 표

`lib/config/jobRequirements.ts`에 정의했습니다. 직무 5개(영업/마케팅/기획/인사/IT) ×
역량 10개, 값은 1~5입니다. **아래 표의 숫자는 제가 상식적인 수준에서 임의로 채운 값**이므로,
실제 회사 기준과 다르면 이 단계에서 바로 고칠 수 있습니다. (승인 후에는 이 파일만 열어
숫자만 바꾸면 언제든 재조정 가능합니다.)

| 역량 \ 직무 | 영업 | 마케팅 | 기획 | 인사 | IT |
|---|---|---|---|---|---|
| 문제해결 | 3 | 4 | 5 | 3 | 5 |
| 데이터분석 | 2 | 4 | 4 | 2 | 4 |
| 커뮤니케이션 | 5 | 4 | 4 | 5 | 3 |
| 리더십 | 3 | 2 | 3 | 4 | 2 |
| 기획력 | 2 | 5 | 5 | 3 | 3 |
| 디지털도구활용 | 2 | 4 | 3 | 2 | 5 |
| 협업 | 4 | 3 | 4 | 5 | 4 |
| 고객이해 | 5 | 5 | 3 | 3 | 2 |
| 재무이해 | 2 | 2 | 4 | 2 | 1 |
| 자기주도학습 | 3 | 4 | 4 | 3 | 5 |

값 수정 방법(나중을 위한 안내): `lib/config/jobRequirements.ts` 파일을 열어 원하는 직무의
숫자만 바꾸면 됩니다. 표 형식이 깨졌는지는 `validateJobRequirements()` 함수가 자동으로
확인하도록 만들어 두었습니다.

## 4. 그 밖에 이번 단계에서 정한 것

- **Gemini 모델명**: `lib/config/constants.ts`의 `GEMINI_MODEL` 상수 한 곳에서 관리 (`gemini-3.5-flash-lite`)
- **관리자 코드**: `lib/config/constants.ts`의 `ADMIN_CODE` 상수 (기본값 `1234`)
- **역량 갭 기준**: 요구수준 − 현재점수 ≥ 2 이면 "우선 보완"
- **재진단 안내 기준**: 완료 항목 3개 이상 쌓이면 배너 표시
- **휴넷 링크**: 실제 검색 주소 형식을 아직 확인하지 못했으므로, 우선 휴넷 메인 주소로 연결 +
  검색어 클립보드 복사 버튼 방식으로 계획 (요청서 지침대로 주소를 지어내지 않음)

## 확인 요청

1. 데이터 구조(4개 표 + 설정 표)가 요청하신 내용과 맞는지
2. 직무별 요구수준 표의 숫자를 이대로 두어도 되는지, 아니면 지금 조정하고 싶은지
3. 개인 API 키 "덮어쓰기"를 브라우저 저장 방식으로 진행해도 되는지

이 세 가지를 확인해 주시면, 다음 단계인 **화면1: 시작 화면**부터 순서대로 만들겠습니다.
